八千代说中文：问题分析与解决方案（调查报告，未实施）
写于 2026-10-03

======================================================================
一、目标（一句话）
======================================================================

八千代用中文主持剧本杀，要同时做到四件事：
  1. 语气和念法像 0 号：自然、平稳、不一惊一乍；
  2. 嗓音像八千代本人；
  3. 普通话咬字、声调准确；
  4. 实时：AI 写完一句，1 秒内开口，念的速度跟得上。

到目前为止，没有一个版本四件事同时做到。

======================================================================
二、为什么一直顾此失彼：把"声音"拆成三层
======================================================================

一句话的声音可以拆成三层，每种技术动的是不同的层：

  第 1 层：内容和咬字。念的是哪些字、每个字的拼音和声调对不对。
  第 2 层：语气（也叫韵律）。音高怎么起伏、快慢、在哪停顿、情绪是平静还是激动。
           "一惊一乍"、"语气正常"说的都是这一层。
  第 3 层：音色（嗓音本身）。同一句话、同样的语气，换一个人念，听起来不同的那部分。
           "像不像八千代"主要是这一层。

关键发现：
  凡是让模型"照着参考录音重新念"的方法（零样本克隆、上下文学习 ICL、Confucius4、Fish），
  都会把参考录音的第 2 层（语气）和第 3 层（音色）一起学过去。

  ● 八千代的原声是动画台词：语气本来就起伏很大、很夸张。
    参考越像她，学来的语气也越夸张，于是就"一惊一乍"。
  ● 0 号之所以语气最正常，是因为它只从原声里拿了一个"音色向量"（一串数字，只粗略描述嗓子），
    语气完全用千问模型自己标准普通话的习惯。代价是：一个向量描述不了她的嗓音，所以不像。

  所以"重新念"这条路，天生就在"像"和"语气正常"之间拉扯：
    参考给得越多越像，语气越夸张；参考给得越少语气越正常，越不像。
  我之前一直在这条路上调参数，这是方向性的错误。

正确的思路是把两件事分开做：
  第一步：让 0 号念（第 1、2 层全部由 0 号决定，语气就是你认可的那种）；
  第二步：只把第 3 层（嗓音）换成八千代，第 1、2 层原封不动。
  第二步这种技术叫"变声"（voice conversion），它不重新念，只换嗓子。

三、已经试过的方案和测量结果
======================================================================

说明：
  "像她"= 用中文训练的声纹模型（CAM++），把合成的声音和她 93 句日语原声的平均声纹比，越高越像。
           参考值：她自己的原声之间互相比，平均约 0.53。
  "句间一致"= 同一个设置合成的 16 句之间互相比，越高越不"飘"。
  "咬字"= Whisper 听写后按拼音逐字核对，16 句里全对几句。
  "速度"= 合成 1 秒语音要花几秒（小于 1 才能实时）。

  方案                                   像她   句间一致  咬字    速度    语气
  -----------------------------------------------------------------------------
  0 号（千问，只用音色向量）              0.47   0.68     15/16   1.1     最正常（你认可）
  现在 App 的声音（千问 + 自参考 ICL）    0.40   0.83     16/16   0.7     平稳偏淡
  千问 + Confucius4 句子当参考             0.53   0.79     14~16   0.7     受参考影响
  Confucius4（她原声当参考）               0.70   0.75     16/16   7.2     一惊一乍（跟着动画原声）
  Fish S2-Pro                             —      —        日式口音 —       —
  GPT-SoVITS 微调                          —      —        日式口音 —       —
  Seed-VC 变声（普通版）                   较像   —        16/16   约 3    声调怪（模型自己重编音高）
  Seed-VC 变声（声调版，就是试听 7）       较像*  —        16/16   约 2    照搬 0 号（声调一致度 0.99）

  * 声调版当时用的是旧打分程序（没有做音量和静音预处理），分数 0.77 和上表其它行不能直接比。
    第五节第 1 步会用同一个打分程序重新测。

结论：
  ● 唯一在原理上能做到"0 号语气 + 她的嗓音"的，是"0 号念 + 变声"这种两段式。
  ● 变声必须"保留源音的音高曲线"，否则声调会变怪。普通版 Seed-VC 的声调一致度只有 0.92~0.94，
    你听出来"声调怪"；声调版是 0.99，声调和 0 号一样。
  ● 两段式现在卡在速度：声调版 Seed-VC 每秒语音要算约 2 秒。

======================================================================
四、解决方案
======================================================================

【推荐】路线 A：0 号念 → 变声只换嗓子 → 实时播放

  流程：
    AI 写完一句 → 0 号（千问，只用音色向量，就是你认可的设置）流式开口
               → 变声器按 0.3~0.5 秒一块边收边换嗓子 → 播放
  语气、咬字、声调全部来自 0 号；变声器只负责嗓子，而且要求它保留 0 号的音高曲线。

  变声器有三个候选，需要实验比较（见第五节第 2 步）：

  A1. Seed-VC 声调版（已经用她 5 分钟原声训练好，模型在 data/LocalTTS/restore/训练存档/）
      优点：质量已验证，声调照搬 0 号。
      缺点：慢。44.1 kHz 的大模型，8 步时每秒语音要算约 2 秒。
      提速方向：扩散步数降到 4~6 步；分块流式（Seed-VC 自带的实时界面就是这样做的）；
                预先算好参考录音的特征；看能否换成 22 kHz 的带音高模型。
      风险：降步数可能让嗓音变糊；苹果芯片上 PyTorch 的显存泄漏（之前训练时遇到过，已有修法）。

  A2. RVC v2（检索式变声，中文社区"AI 配音 / AI 翻唱"的标准做法）
      优点：本来就是为"保留原音高、只换音色"设计的，速度很快，可以实时；
            5~10 分钟数据就能训练出很像的动画角色嗓音；有苹果芯片专用版本。
      缺点：要重新训练（预计 0.5~2 小时）；音质可能有轻微"电音"；
            训练时要下载预训练文件（hubert 约 190 MB、RMVPE 音高模型约 180 MB、底模几百 MB）。
      风险：在苹果芯片 GPU（MPS）上训练的稳定性要实际验证。

  A3. Seed-VC 实时小模型（xlsr-tiny，2500 万参数）
      优点：官方测得速度 0.07（极快），实时延迟约 430 ms。
      缺点：要确认它是否保留源音音高；如果像普通版那样自己重编音高，声调又会怪；
            小模型音色相似度可能不如大模型。需要用她的数据微调。

  路线 A 的总延迟估算：0 号第一块约 0.3 秒 + 变声第一块 0.15~0.5 秒 ≈ 0.5~1 秒开口。

  路线 A 的成本：
    ● App 里要串联两个后台服务（千问 → 变声器），我之前已经写过一版这样的串联，后来删了，可以恢复。
    ● 内存：千问 8 位约 3~4 GB，变声器 1~2 GB，在 16 GB 的 Mac 上可以接受。

【备选】路线 B：用路线 A 的输出去微调千问，变成一步到位

  做法：先用路线 A 离线生成 300~500 句"0 号语气 + 她嗓音"的中文（不要求实时，可以开大步数保证质量），
        再拿这些中文录音按千问官方方法做"专属说话人微调"。
  结果：千问一次合成就是目标声音，速度和现在一样实时（0.7），而且训练数据本身就是中文，
        不会有日式口音；语气来自 0 号，也不会一惊一乍。
  缺点：最费时（生成 1~2 小时 + 训练 1~3 小时）。
        官方脚本是全量微调 1.7B 模型，需要 20 GB 以上内存，16 GB 的 Mac 不够，
        要改成训练 0.6B 模型或者只训练一小部分参数（LoRA），需要改写官方脚本。
  适合：路线 A 的音质令人满意但速度做不到实时的时候。

【不推荐】
  ● 继续在"重新念"的路子上调参数（ICL、换参考句、调温度）：原理上做不到两全，第二节已经说明。
  ● Confucius4 直接上线：太慢（7 倍），而且语气跟着动画原声的夸张走。
    可以试她原声里语气平静的片段（比如深夜那句"もう遅い時間だよ……"）当参考，可能减轻一惊一乍，
    但速度问题解决不了。

五、建议的调查步骤（每一步先验证再往下走）
======================================================================

第 0 步：你先听试听 7（今天已发）  ← 最关键，决定方向
  如果 7 的语气和 0 号一样、嗓音更像她，说明路线 A 方向对，只剩速度问题。
  如果 7 嗓音还不够像，要说清楚差在哪：音高偏低、声音发闷、不够亮、不够可爱……
  因为变声器只管嗓子，这些都可以针对性调整，不会影响语气。

第 1 步：统一打分口径（约 30 分钟）
  用同一个打分程序给 0 号、7 号、Confucius4、现在 App 的声音重新打分。新增一组"语气保真"指标：
    ● 和 0 号源音的音高曲线相关度（声调和语调有没有被改）；
    ● 语速比、停顿位置和长度是否一致；
    ● 句内音高起伏（衡量"一惊一乍"的程度，起伏越大越夸张）。
  通过标准：语气保真度 ≥ 0.98，像她 ≥ 0.6（真声互比约 0.53），咬字 16/16。

第 2 步：变声器对比实验（半天）
  同一批 0 号源音（16 句测试句 + 5 句长句/短句），分别用 A1（8/6/4 步）、A2（RVC）、A3（tiny）变声。
  比较：像她、语气保真、咬字、速度、有没有杂音电音。
  挑出 2 个候选给你盲听（不告诉你哪个是哪个），由你选。

第 3 步：实时性验证（2~3 小时）
  ● 分块流式变声：开口延迟、每秒语音的计算时间、分块接缝处有没有咔哒声；
  ● 连续合成 300 句的内存和速度变化（防止之前遇到过的内存越用越多）；
  ● 和 Live2D、AI 同时运行时的速度。
  通过标准：开口 < 1 秒，计算速度 < 0.8（留余量），连续 2 小时不变慢。

第 4 步：接入 App 的设计（确认后再做）
  ● 两个后台服务串联；任何一步失败就退回 0 号原声，保证每句都念出来；
  ● 语音缓存的键加入变声模型指纹，换模型时旧缓存自动作废；
  ● 设置里可以一键切换"0 号原声 / 0 号 + 八千代嗓音"。

第 5 步：你在真实游戏里听一局验收。

如果第 2、3 步证明任何变声器都做不到实时 → 走路线 B（用变声结果离线生成数据，微调千问）。
