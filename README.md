# AI 剧本杀主持（Mac 版）

让 AI 当 DM，大家坐在一起用手机玩。Mac 上运行应用：主持台控制流程，大屏投到电视，每人手机扫码选角色。
支持云端大模型和本地模型（Ollama / LM Studio），可以导入扫描版剧本，还可以给 DM 配一个 Live2D 形象和克隆音色。

```
          ┌──────────────── Mac 应用（AI 剧本杀.app）────────────────┐
          │  主持台（原生界面）  流程控制 · 记录讨论 · 发线索 · AI 记忆   │
          │  大屏（原生窗口）    主持词 · 计时 · 线索 · Live2D DM 形象    │
          │  游戏引擎            状态机 · 自动存档 · 记忆压缩 · 防剧透    │
          │  内置网页服务        手机端页面（同一个 Wi‑Fi 扫码进入）      │
          └──────────────────────────┬────────────────────────────────┘
                                     │  AI（云端或本地，OpenAI 兼容接口）
                手机浏览器 /player：剧本 · 线索 · 搜证 · 问 DM · 投票
```

**Quick start (English):** on a Mac with macOS 14+, install the Xcode command line tools (`xcode-select --install`), then run `./build.sh` and open `build/AI 剧本杀.app`. Pick the demo script and click 开始游戏. Players join by scanning the QR code on the big screen with their phones (same Wi‑Fi).

## 一、安装

需要 macOS 14 以上。只需要 Xcode 命令行工具，不需要完整的 Xcode：

```bash
xcode-select --install
```

然后在项目文件夹里：

```bash
./build.sh
```

生成的应用在 `build/AI 剧本杀.app`，双击打开，或者拖进“应用程序”文件夹。
第一次打开如果提示“无法验证开发者”：在 Finder 里右键应用 →“打开”。
第一次开局时 macOS 会问“是否允许接受传入的网络连接”，请点 **允许**，否则手机连不上。

## 二、5 分钟先跑起来（不用 AI，模拟模式）

1. 打开应用，剧本库里有原创示例剧本《听涛居》（4 人），点 **开始游戏**。
2. 主持台工具栏点 **大屏** 打开大屏窗口，或者点 **投屏** 直接全屏放到电视/投影上。
3. 手机和 Mac 连同一个 Wi‑Fi，扫大屏上的二维码选角色。
4. 主持台点 **下一阶段** 推进流程：AI 念主持词，手机自动解锁新一幕剧本、切到搜证/投票页。

快捷键：⌘→ 下一阶段，⌘← 上一阶段，⌘R 重播旁白，⌘B 打开大屏。

## 三、接上 AI

**设置（⌘,）› AI 主持**，选一个服务、填 API Key、点“测试连接”：

| 服务 | 说明 |
|---|---|
| DeepSeek | 便宜、中文好，相同开头的请求自动缓存，很适合本系统 |
| 通义千问（阿里云百炼） | 百炼控制台申请 Key |
| Claude | 守秘密能力强（OpenAI 兼容接口） |
| 本地 Ollama | 先装 Ollama，`ollama pull qwen2.5:14b`；7B~14B 需要 8~16GB 内存/显存 |
| 本地 LM Studio | 加载模型并开启 Local Server |

API Key 保存在 macOS 钥匙串里。主持和判定需要较强的推理和守秘密能力，越强的模型越不容易剧透、说错。
**设置 › 记忆压缩** 可以把记忆压缩这种简单活交给便宜/本地小模型，省钱。

## 四、导入你们的剧本（扫描版 PDF）

**文件 › 导入扫描剧本（⌘I）**：

1. **添加文件**：把 DM 手册、角色本、线索卡的 PDF 拖进来，给每个文件选好类型（角色本要填角色名）。只有 DM 手册也可以，角色会从手册里提取。
2. **识别文字**：默认用苹果自带的中文文字识别（离线、免费）。扫描件一页是左右两页就勾“切开识别”；字小选“字小用这个”。版面很乱可以改用 AI 视觉模型（设置 › 识别）。识别过的页会缓存，中途关掉下次接着做。识别完可以“查看/修改文字”，把认错的人名、时间改掉。
3. **AI 整理**：角色本按“第X幕”自动分幕、原文照搬；DM 手册和线索卡交给 AI 提取真相、流程、主持词、搜证地点和线索、凶手、结局。没有 AI 也可以“生成空白骨架”自己填。

整理完会打开 **剧本编辑器**，用表单逐项检查（必做）：

- 阶段顺序和每个阶段的类型
- 每个搜证地点放了哪些线索（最容易错）
- 真相是否完整——AI 回答问题、最后复盘全靠它
- 凶手（投票阶段的正确答案）、防剧透禁用词
- 角色的秘密摘要（给 AI 看的）

编辑器右侧随时显示检查结果，⌘S 保存。示例剧本是只读的，要改请在剧本库“复制一份来修改”。

**多重解答的剧本**（前面的答案会被后面推翻）：防剧透禁用词可以写成 `说法@阶段id`，表示到那个阶段才解禁，例如 `凶手是铃木美雪@p3_05`、`两座六角馆@p5_13`。不写 `@` 的禁用词在第一个“复盘”阶段（或 `dm.forbidden_until` 指定的阶段）解禁。

命令行也能识别、检查：

```bash
"build/AI 剧本杀.app/Contents/MacOS/AIDM" --ocr 剧本.pdf [--split] [--dpi 300]
"build/AI 剧本杀.app/Contents/MacOS/AIDM" --check 剧本文件夹 [--rewrite]
```

剧本、存档、识别结果、语音模型都在项目文件夹的 `data/` 里（剧本库页面底部有链接；`data/` 不会上传到 GitHub）。项目文件夹外运行时改用 `~/Library/Application Support/AI DM/`。

## 五、DM 形象（Live2D）

**设置 › DM 形象**：点“导入 Live2D 模型…”选模型文件夹（里面有 `.model3.json`，支持 Cubism 3/4/5），也可以直接把文件夹拖到预览框里。

- 形象站在大屏字幕旁边，DM 说话时对口型（开了克隆音色时按真实音量），说话时看向字幕。
- 换阶段时做个动作：模型有动作文件就播放，没有（比如 VTube Studio 导出的模型）就点头/歪头。
- 表情：自动识别文件夹里的 `.exp3.json`（即使 model3.json 里没登记）。复盘投对了笑、投错了哭，AI 思考公开问题时眯眼——按表情名字里的关键词（笑/泪/眯）匹配。
- “取景”可以选全身/半身/特写，也可以拖滑块调大小和位置、选站在字幕左边还是右边。
- 8K 贴图导入时会自动缩到 4096（大屏上看不出区别，加载快很多），原文件不动。
- Live2D 官方运行库（Cubism Core）第一次使用时从 Live2D 官网自动下载。模型版权归原作者，请遵守模型的使用条款。

命令行导入：`AIDM --import-live2d 模型文件夹`

## 六、DM 的声音

默认用**八千代的本机音色**（`data/LocalTTS/voices/yachiyo/八千代`）：在这台 Mac 上用 Qwen3-TTS（mlx-audio，苹果芯片）合成，不联网、不花钱，普通话标准。

- **语音默认开着，DM 的每句话都会念出来**：旁白、复盘、当面提问的回答、手机上公开提问的回答。只回答某个玩家的私聊不念（免得别人听到）。顶栏 🔊 可以临时关掉，下次打开 App 会记住。
- 偶尔合成失败会自动重试；连续失败才临时用系统声音念这一句，保证不漏句、不卡住游戏。
- **实时朗读**：AI 写完一句，约 0.2～0.7 秒八千代就开口（很长的一串话会从逗号、分号处先开口）；边合成边播放，上一句还在念时下一句已经在合成，句子之间不停顿。模型压成 8 位运行（苹果芯片上快一倍多，音质基本不变），每秒能合成约 1.6 秒的语音。
- 打开 App 时在后台加载声音模型（约 5 秒），开局第一句就能马上念。念过的句子会存起来，再念同一句直接播放。
- 剧本里固定的台词也可以提前生成（可选，一般不需要）：`AIDM --pregen 剧本.yaml`，或者 设置 › 语音 › “生成并保存到本机”。
- 测一下延迟：`AIDM --speak-test`（静音模拟 AI 一边写一边念，打印第一声多久出来）。
- 试一句：`AIDM --local-tts yachiyo/综合 "各位侦探，欢迎来到六角馆。" out.wav`

**音色文件夹**（`data/LocalTTS/voices/<名字>/`）：`ref.wav` 参考录音、`ref.txt` 原话，可选 `voice.json` 合成参数：

```json
{"icl": true, "temperature": 0.4, "top_k": 50, "top_p": 1.0, "repetition_penalty": 1.1, "streaming_interval": 0.5}
```

- `icl: true` = 用“参考录音 + 原话”做上下文学习，每句都锚定在同一段发音上，音色最稳、咬字最准。参考录音必须和要说的话是同一种语言——八千代只有日语原声，所以 `yachiyo/八千代` 用的参考是**她自己念过、经声纹和咬字双重挑选的一句中文**（“自参考”），日语原声只用来生成这句锚点。
- 没有 `voice.json` 的音色只学音色向量（`yachiyo/综合`），每句独立采样，音色会有些飘。
- 换了 `ref.wav` / `ref.txt` / `voice.json`，App 会自动把之前缓存的句子作废（缓存键里带音色指纹）。

**调音色用的工具**（`Resources/localtts/`，都在这台 Mac 上离线跑）：

- `tune_voice.py`：同一组中文句子用几十种合成设置各合成一遍（温度、采样、8 位/bf16、流式/一次性、ICL 自参考、声学码本单独降温……）。
- `score_consistency.py`（用 `seedvc-venv`）：两个声纹模型（Resemblyzer + 中文训练的 CAM++）给每种设置打“句与句之间像不像”“和认可的声音像不像”“和真声像不像”，再加音高离散、生动程度、第一声延迟；同种子配对还能按 80 ms 码元对齐看流式解码器有没有在分块边界出瑕疵。
- `asr_check.py`：Whisper 听写后按拼音和原文核对，普通话咬字是硬门槛。

调音色时发现并修掉的 mlx-audio 问题：流式解码器在每个分块边界把反卷积偏置加了两次（每 0.48 秒一个小瑕疵，同种子对比相对误差中位数 16%）；`server.py` 启动时打补丁，修后流式输出和一次性解码逐样本一致。

**设置 › 语音** 里也能换成系统自带语音，或者阿里云 Qwen 云端克隆音色（需要百炼 API Key，音色 ID 只在创建它的账号里能用）。克隆音色请仅用于个人娱乐。

## 七、游戏当天

1. 开局后大屏投到电视，大家扫码选角色。
2. 主持人按 **下一阶段** 推进，AI 自动念主持词，手机自动解锁新一幕剧本、切到搜证/投票页。
3. **搜证**：手机上点地点，按顺序抽线索卡，每人有次数限制。线索默认私有，可以点“公开”。
4. **问 DM**：私下问自己剧本的问题，或者公开提问（显示在大屏）。有些线索要问对了才给。
5. **记录线下讨论**：大家面对面说的话 AI 听不见。主持台“记录讨论要点”里记一句关键内容，AI 主持和最后复盘都会用到。
6. **投票** 后进入复盘，AI 结合投票结果和游戏过程讲真相。
7. 中途停下：直接结束，下次在剧本库点 **继续** 会接着存档玩。

有人换手机/手机没电：主持台“玩家”里对应角色点“…› 释放”，新手机重新选这个角色，线索和进度都在。

## 八、长时间游戏的上下文问题是怎么解决的

不是让 AI 记住十个小时的对话，而是每次调用时重新拼一份 **长度固定** 的上下文：

| 内容 | 来源 | 长度 |
|---|---|---|
| 身份、规则、真相、角色一览 | 剧本，整局不变 | 固定（云端可命中前缀缓存） |
| 当前阶段、主持提示、已公开线索 | 程序状态 | 小 |
| 之前发生的事 | **摘要**，超过阈值自动压缩 | ≤600 字 |
| 最近 30 条公开事件 | 原样 | 固定条数 |
| 提问玩家的剧本、线索、最近私聊 | 只给这一个人的 | 小 |

- **流程由程序控制**：第几阶段、谁有哪些线索、搜证还剩几次、谁投了谁，全在存档里，AI 不用记。
- **线索由程序把关**：AI 只能从本阶段允许的线索里选，程序校验后才发出。
- **防剧透**：真相公开之前，回复里出现禁用词会被拦截重答（主持台“提醒”里有记录）。旁白调用根本不给 AI 看真相。可以用 `dm.forbidden_until` 指定从哪个阶段开始可以说出真相（适合没有投票、在最后几章揭晓真相的剧本）。
- **私密隔离**：A 的私聊和角色本不会进入 B 的上下文。

主持台“记忆”里能看到当前摘要和压缩情况。

## 九、常见问题

**手机打不开链接**：手机和 Mac 必须连同一个 Wi‑Fi；第一次开局时的防火墙弹窗要点“允许”（系统设置 › 网络 › 防火墙里也能改）；有的路由器开了“AP 隔离”会挡住设备互访。

**AI 说漏嘴了**：把漏掉的说法加进防剧透禁用词；或者换更强的模型；或者把秘密摘要、主持提示写得更明确。

**本地模型回答很慢**：调大超时；换小一点的模型；或者主持用云端、只把记忆压缩交给本地。

**推理模型（Qwen3、DeepSeek-R1）的思考过程**：会自动去掉，不会显示和念出来。

## 十、文件结构

```
Package.swift            Swift 包（依赖：Yams）
build.sh                 编译并打包成 .app
Sources/AIDM/
  App/                   入口、窗口、设置与剧本库（AppModel）
  Core/                  游戏引擎、剧本加载与校验、状态存档、提示词、AI 接口
  Server/                内置网页服务（手机端接口 + SSE 推送）
  UI/                    剧本库、主持台、大屏、导入向导、剧本编辑器、设置
  Live2D/                Live2D DM 形象（WKWebView + PixiJS）
  Import/                OCR（Vision）与 AI 整理
  Util/                  语音（本机 Qwen3-TTS / 系统 / 阿里云云端音色）、二维码、钥匙串等
Resources/
  web/                   手机端页面
  live2d/                Live2D 渲染页（PixiJS、pixi-live2d-display，均为 MIT）
  localtts/              本机语音服务（server.py，Qwen3-TTS）、做音色和调音色的工具（prepare_voice / tune_voice / score_consistency / asr_check）
  Demo/                  示例剧本《听涛居》
```
