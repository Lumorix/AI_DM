# AI 剧本杀主持（线下同屋版）

让 AI 当 DM，大家坐在一起用手机玩。一台电脑开服务，电视/投影显示大屏，每人手机扫码选角色。
支持云端大模型和本地模型（Ollama / LM Studio），改一行配置就能切换。

```
          ┌──────────── 电脑（运行 run.py）────────────┐
          │  流程控制（状态机） ← 剧本 script.yaml     │
          │  游戏状态（自动存档 saves/）               │
          │  记忆压缩（摘要）   → AI（云端或本地）     │
          └──────┬──────────────┬──────────────┬───────┘
            大屏 /screen    手机 /player    管理 /admin
          旁白·计时·线索   剧本·搜证·问DM   推进·记录·发线索
```

## 一、5分钟先跑起来（不用AI，模拟模式）

需要 Python 3.10 以上。

**Windows**：双击 `start.bat`（第一次会自动安装依赖）
**Mac / Linux**：终端里运行 `bash start.sh`

或者手动：
```bash
pip install -r requirements.txt
python run.py
```

启动后命令行会打印三个链接：
- **大屏**：在电脑浏览器打开，投到电视上。点“语音朗读”可以让电脑念出DM的话。
- **玩家**：手机扫大屏上的二维码（手机和电脑要连同一个WiFi）。
- **管理**：带 `?admin=` 的那个，用来推进流程。可以在电脑上另开一个窗口，或者发给一个人的手机。

自带一个原创示例剧本《听涛居》（4人），先用它熟悉流程。

## 二、接上AI

复制 `config.example.yaml` 为 `config.yaml`，把 `provider` 改成 `openai`，填上地址、key、模型名。文件里有各家的写法示例。

**云端**（推荐先用这个）：DeepSeek、通义千问、Claude、OpenAI 等。要点：
- 主持和判定需要较强的推理能力和守秘密能力，越强的模型越不容易剧透、说错。
- DeepSeek 等服务对相同开头的请求有自动缓存，本系统把不变的剧本内容固定放在最前面，正好能用上。

**本地**：
1. 安装 [Ollama](https://ollama.com)，命令行运行 `ollama pull qwen2.5:14b`（或其他中文好的模型）
2. config.yaml 里：
   ```yaml
   llm:
     provider: openai
     base_url: http://localhost:11434/v1
     api_key: ollama
     model: qwen2.5:14b
     timeout: 600
   ```
3. 显存参考：7B~14B 需要 8~16GB；30B 级别需要 24GB（3090/4090）或 32GB 以上内存的 M 系列 Mac。
   小模型更容易剧透和搞混线索，本系统有程序兜底（见下文），但体验还是大模型好。

**混合用法**：主模型用云端，`cheap:` 部分配本地小模型专门做记忆压缩，省钱。

## 三、把你们的剧本放进来

你们的剧本是扫描图片的PDF，分三步：

### 1. 识别文字（OCR）
```bash
pip install rapidocr_onnxruntime      # 本地OCR，免费，中文效果好
python -m tools.ocr 剧本文件夹/*.pdf --out work
```
- 扫描件一页是摊开的左右两页：加 `--split`
- 字小、识别差：加 `--dpi 300`
- 版面很乱（表格、竖排、手写）：用视觉大模型 `--engine vision`（在 config.yaml 的 `vision:` 里配 Qwen-VL 等模型）
- 中途断了重新运行，已识别的页会跳过

结果在 `work/文件名.txt`，建议打开扫一眼，人名、时间识别错的顺手改掉。

### 2. 让AI整理成剧本文件
```bash
python -m tools.draft --out scripts/我们的剧本 \
    --dm work/DM手册.txt \
    --char 角色A=work/角色A.txt --char 角色B=work/角色B.txt \
    --clues work/线索卡.txt
```
- 角色本按“第X幕”自动分幕，**原文照搬**，不让AI改写。
- DM手册和线索卡交给AI提取：真相、阶段流程、主持词、搜证地点和线索、凶手、结局。

### 3. 人工检查（必做）
打开 `scripts/我们的剧本/script.yaml`，对照示例 `scripts/demo/script.yaml` 检查：
- **阶段顺序**和每个阶段的类型
- **每个搜证地点放了哪些线索**（这是最容易错的地方）
- **真相（dm.truth）是否完整**——AI回答问题、最后复盘全靠它
- **凶手（vote.answer）**、**防剧透词（dm.forbidden）**
- 角色的 `secret_brief`（给AI看的秘密摘要）是否准确

检查命令：
```bash
python -m jubensha.script scripts/我们的剧本
```

> 嫌命令行麻烦也可以：把 OCR 出来的文字和 `scripts/demo/script.yaml` 一起发给 Claude / ChatGPT 这类长上下文聊天助手，让它照这个格式整理。

运行：
```bash
python run.py --script scripts/我们的剧本 --new
```

## 四、游戏当天

1. 运行 `run.py`，大屏投到电视，大家扫码选角色。
2. 管理员按“下一阶段”推进，AI 自动念主持词，手机自动解锁新一幕剧本、切到搜证/投票页。
3. **搜证**：手机上点地点，按顺序抽线索卡，每人有次数限制。线索默认私有，可以点“公开”。
4. **问DM**：私下问自己剧本的问题，或者公开提问（显示在大屏）。有些线索要问对了才给。
5. **记录线下讨论**：大家面对面说的话AI听不见。管理员在管理页简单记一句关键内容（谁承认了什么、谁指控谁），AI 主持和最后复盘会用到，复盘会更有针对性。
6. **投票**后进入复盘，AI 结合投票结果和游戏过程讲真相。
7. 中途想停下来：直接关掉，下次运行 `run.py`（不加 `--new`）会接着存档继续。

有人换手机/手机没电：管理页对应角色点“释放”，新手机重新选这个角色，线索和进度都在。

## 五、10小时上下文问题是怎么解决的

不是让 AI 记住10小时的对话，而是每次调用时重新拼一份**长度固定**的上下文：

| 内容 | 来源 | 长度 |
|---|---|---|
| 身份、规则、真相、角色一览 | 剧本，整局不变 | 固定 |
| 当前阶段、主持提示、已公开线索 | 程序状态 | 小 |
| 之前发生的事 | **摘要**，超过阈值自动压缩 | ≤600字 |
| 最近30条公开事件 | 原样 | 固定条数 |
| 提问玩家的剧本、线索、最近私聊 | 只给这一个人的 | 小 |

- **流程由程序控制**：现在第几阶段、谁有哪些线索、搜证还剩几次、谁投了谁，全在 `saves/` 的状态文件里，AI 不用记。
- **线索由程序把关**：AI 只能从本阶段允许的线索里选，程序校验后才发出。
- **防剧透**：复盘前，回复里出现 `dm.forbidden` 里的词会被拦截重答，管理页有记录。旁白调用根本不给 AI 看真相。
- **私密隔离**：A 的私聊内容和角色本不会进入 B 的上下文。

管理页“AI 的记忆”里能看到当前摘要和压缩情况。

## 六、配置说明（config.yaml）

| 配置 | 说明 |
|---|---|
| `llm.provider` | `openai`（任何OpenAI兼容接口）或 `mock`（测试） |
| `llm.cheap` | 可选，摘要用的便宜/本地模型 |
| `game.narration` | `ai` 润色后念主持词；`verbatim` 原文照念（最稳）。管理页可随时切换 |
| `game.memory.keep_recent` | 原样保留多少条最近公开事件 |
| `game.memory.summarize_batch` | 攒多少条压缩一次 |
| `game.memory.private_keep` | 每人原样保留多少条私聊 |

## 七、常见问题

**手机打不开链接**：手机和电脑必须同一个WiFi；Windows 第一次运行时防火墙弹窗要点“允许”；有的路由器开了“AP隔离”会挡住设备互访。

**大屏没有二维码**：没装 `segno` 且电脑不能上网。`pip install segno` 即可，或者让大家手动输入网址。

**语音朗读没声音**：浏览器要求先点一下页面才能出声，点大屏的“语音朗读”按钮。Chrome / Edge 的中文语音最好。

**AI 说漏嘴了**：把漏掉的说法加进 `dm.forbidden`；或换更强的模型；或把 `secret_brief`、`dm_notes` 写得更明确。

**本地模型回答很慢**：调大 `timeout`；换小一点的模型；或主持用云端、只把摘要交给本地。

**推理模型（Qwen3、DeepSeek-R1）的思考过程**：会自动去掉，不会显示和念出来。

## 八、文件结构

```
run.py                启动入口
config.example.yaml   配置模板
jubensha/
  engine.py           游戏引擎：阶段推进、搜证、问答、投票、记忆压缩、防剧透
  prompts.py          所有提示词（想调AI风格改这里）
  llm.py              AI接口（OpenAI兼容 / 模拟）
  script.py           剧本加载与校验
  state.py            游戏状态与存档
  server.py           网页服务
  static/             大屏、玩家、管理三个页面
tools/
  ocr.py              扫描PDF → 文字
  draft.py            文字 → script.yaml 初稿
scripts/demo/         示例剧本《听涛居》
saves/                自动存档
```

## 九、还可以加的功能

- **语音输入**：大屏开浏览器语音识别或接 Whisper，把大家的讨论自动转成“讨论要点”，不用管理员手打。
- **NPC 扮演**：剧本里需要演的角色，单独起一个只知道该角色信息的 AI。
- **TTS 角色配音**：接 edge-tts / CosyVoice 等，给 DM 和 NPC 不同音色。
- **氛围**：按阶段切换 BGM、在 script.yaml 里给阶段配背景图。
- **线索图片**：线索卡扫描图放进剧本文件夹，在 clue 里写 `image: assets/c1.jpg` 即可在手机上显示。
